What each control does here

On the MiniLab 3 itself

The hardware screen holds only two short lines, about 18 and 15 characters. Turning a knob shows its name and value for about a second, then the location comes back. The pads light in the same colours as the pads above.

The same in all three

  • Knobs 1–4 on the home page are the sound's four macros. Each knob keeps its role on every sound (1 tone, 2 character, 3 time, 4 movement), and each sound gives it its own name. For Neon Brass they are Blare, Thickness, Swell and Shimmer.
  • Knobs 6–8 do the same thing on every page: Glide, Brightness and Space.
  • Faders are the mixer: Part A, Part B, Effects and Master. A fader picks its value up only when it passes the stored one.
  • Pads 1–4 open Sound, Shape, Motion and Effects, each in its own colour. Press the lit pad again to go to the next slot.
  • Pads 5–7 are kept for the recorder: stop, play, record.
  • Pad 8 goes home. Shift + pad 8 switches between Part A and Part B. This one is my proposal, not yet your choice.
  • Shift + pad 1 (printed "Arp") opens Perform: arp, chord and voice settings.
  • Shift + press on the main knob goes back. Shift + any knob turns it ten times finer.

What the hardware allows

  • Only the MiniLab's DAW program lets software write its screen and pad colours. The app enters it with a short message the hardware answers, the same one Ableton's own script sends. Ableton MiniLab 3 script · Arturia forum, reverse-engineered protocol
  • Knobs 1–8 turn endlessly but report absolute values in that program. The app can reset a knob's stored value whenever the page changes, so nothing jumps. Knob 5 works as a navigation knob by reading each change and putting the value back in the middle.
  • The main knob sends separate messages for turn, press, Shift + turn and Shift + press. Shift sends its own message too, so Shift combines with anything.
  • The screen shows two text lines plus knob and fader pop-ups. The pads take any RGB colour, set per pad.
  • The faders are absolute, and the hardware does no pickup. The app has to do it.
  • Hold, Oct and the touch strips may work only inside the keyboard. Nothing confirms they reach the app, so none of the three mock-ups depends on them.
  • Inside a DAW, the DAW's own MiniLab script would fight the plugin for the screen and lights. A standalone app that owns the MiniLab port has no such conflict.
